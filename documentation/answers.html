Seeded bugs

The answer key for the missions: every deliberate bug in the seeded version of the pages used so far, 104 in all. Do the mission for a session first, on your own, with the steps in the documentation. Then come here to see whether your findings are right and complete.

For each bug you get where it is, what goes wrong for the user, how to find it, the WCAG 2.2 success criterion it fails (or that it is a best practice), and the right way to build it. The right way is what the accessible version does, so you can inspect it there.

Automated tools find only some of these. Where a bug says axe DevTools, axe reports it; everything else you find with the keyboard, the accessibility tree, a screen reader or your eyes. A level A or AA criterion is a failure; a best practice is not, but users still notice it.

Bugs on pages for sessions that have not happened yet, such as the New agent form, are not listed.

On every page

These bugs are in the top bar and the page frame of the seeded version, so you meet them on every screen. They count for every session. The Home page has no bugs of its own: these six are all you will find there.

  1. No skip link

    Where
    The first Tab stop on every page.
    What is wrong
    There is no "Skip to main content" link. A keyboard user has to Tab through the logo, Documentation, Help and the whole sidebar on every page before reaching the content.
    How to find it
    Keyboard: press Tab once after the page loads.
    WCAG 2.2
    2.4.1 Bypass Blocks, A
    The right way
    The first element on the page is a link, <a href="#main">Skip to main content</a>. It appears when it gets focus and moves the focus into main.

  2. The logo has no text alternative

    Where
    The Agent Studio logo at the top left.
    What is wrong
    The image has no alt attribute, so a screen reader reads the file name or just "image".
    How to find it
    axe DevTools (image-alt) · Accessibility pane · screen reader.
    WCAG 2.2
    1.1.1 Non-text Content, A
    The right way
    alt="Agent Studio": the alt text repeats the text in the logo.

  3. The Help button is hidden from screen readers

    Where
    The round question mark button at the top right.
    What is wrong
    The button has aria-hidden="true" and no name. Keyboard users can Tab to it, but a screen reader announces nothing: a focus stop with nothing to say.
    How to find it
    axe DevTools (aria-hidden-focus) · Accessibility pane · screen reader.
    WCAG 2.2
    4.1.2 Name, Role, Value, A
    The right way
    No aria-hidden on the button, and the name "Help" with aria-label. Only the icon inside it is hidden. Removing the button from the Tab order, as axe suggests, would take it away from keyboard users.

  4. Documentation is a fake link

    Where
    The Documentation button in the top bar.
    What is wrong
    It is a span with role="link", opened by script. Enter works, but it has no address, so the browser's link features (open in new tab, copy link) do not work, and nothing says it opens in a new tab.
    How to find it
    Accessibility pane or Elements panel · mouse: right-click shows no link menu.
    WCAG 2.2
    Best practice: use the native element (the first rule of ARIA).
    The right way
    A real <a href> that says "(opens in a new tab)" in its name.

  5. The page title never changes

    Where
    The browser tab, on every page.
    What is wrong
    The title stays the same whichever page you open. Screen reader users get no confirmation of where they are, and tabs and history all look alike.
    How to find it
    By eye: look at the browser tab while you move between pages.
    WCAG 2.2
    2.4.2 Page Titled, A
    The right way
    Every page sets its own title, for example "Agents – Agent Studio playground".

  6. Focus stays behind after you open another page

    Where
    After a sidebar link, an agent card, a table row or a Back button.
    What is wrong
    The content changes but the focus does not follow. Either it stays on the sidebar link, so a screen reader announces nothing new, or it drops to the top of the document.
    How to find it
    Keyboard: press Enter on a link, then Tab, and see where you are.
    WCAG 2.2
    2.4.3 Focus Order, A
    The right way
    After a page change, the focus moves to the new page's main heading, so its name is read and Tab continues in the new content.

Session 2: Agents page

The Agents page in Card view and List view, the More actions menu, the Rename and Delete dialogs, and an agent page opened from the list. The New agent form belongs to a later session and is not listed.

The page: seeded version · accessible version

  1. The Refresh button has no name

    Where
    The round arrow button next to the Agents heading.
    What is wrong
    The icon-only button has no accessible name. A screen reader says only "button".
    How to find it
    axe DevTools (button-name) · Accessibility pane.
    WCAG 2.2
    4.1.2 Name, Role, Value, A
    The right way
    aria-label="Refresh project list" on the button; the icon stays hidden.

  2. The Card and List switch does not say which view is on

    Where
    The Card and List toggle above the agents.
    What is wrong
    Two plain buttons. Only the colour shows the current view, so a screen reader hears "Card, button" and "List, button" with no selected state, and nothing groups them.
    How to find it
    Accessibility pane: no pressed or checked state · screen reader.
    WCAG 2.2
    4.1.2 Name, Role, Value, A
    The right way
    A fieldset with the hidden legend "View" and two radio buttons styled as a switch. The checked state is native and the arrow keys move between them.

  3. Search results are not announced

    Where
    The Search Agents box.
    What is wrong
    Typing filters the agents silently. A screen reader user does not hear how many agents match, or that none do.
    How to find it
    Screen reader: type in the box and listen.
    WCAG 2.2
    4.1.3 Status Messages, AA
    The right way
    A hidden status region (role="status") says "3 agents match" shortly after typing stops.

  4. The New agent button is called "Agents"

    Where
    The greyed-out New agent button at the top right.
    What is wrong
    The button's name comes from aria-labelledby, which points at the page heading, so its accessible name is "Agents". It does not say what the button does, and a voice control user who says "click New agent" gets nothing.
    How to find it
    Accessibility pane: expand Name to see which source wins.
    WCAG 2.2
    2.5.3 Label in Name, A
    The right way
    No aria-label and no aria-labelledby: the visible text "New agent" is the name.

  5. Why New agent is unavailable is shown only on hover

    Where
    The New agent button and its tooltip "You do not have permissions at the moment."
    What is wrong
    The button is disabled, so Tab skips it, and the reason is only in a mouse tooltip. Keyboard and screen reader users never learn why they cannot create an agent.
    How to find it
    Mouse: hover the button · keyboard: Tab skips it.
    WCAG 2.2
    Best practice / usability (disabled controls are allowed to be skipped, but the reason must reach everyone).
    The right way
    The control stays focusable with aria-disabled="true", and a real tooltip appears on hover and on focus and closes with Escape.

  6. The card list is not a proper list

    Where
    Card view, the grid of agent cards.
    What is wrong
    The ul contains links directly instead of list items, so screen readers may not announce the list or its size correctly.
    How to find it
    axe DevTools (list).
    WCAG 2.2
    1.3.1 Info and Relationships, A
    The right way
    Each card is an li inside the ul.

  7. The whole card is one link with a button inside

    Where
    Card view, each agent card.
    What is wrong
    The whole card is one link, so its name is everything in it: name, description, "More actions" and the last-edited line. The More actions button sits inside that link: a control inside a control.
    How to find it
    Accessibility pane: read the link's name · screen reader: links list.
    WCAG 2.2
    4.1.2 Name, Role, Value, A
    The right way
    Only the agent name is a link. The More actions button sits next to it, inside the list item.

  8. Table rows are fake links

    Where
    List view, each row.
    What is wrong
    Each row has role="link" and tabindex="0". That replaces the row role, so screen readers lose the table structure, and the whole row becomes one long link name with a button inside.
    How to find it
    Accessibility pane: the row role is gone · keyboard: the whole row gets focus.
    WCAG 2.2
    1.3.1 Info and Relationships, A · 4.1.2 Name, Role, Value, A
    The right way
    The row stays a normal table row and the agent name in the first cell is a real link.

  9. The sort order is shown only by an arrow

    Where
    List view, the Name and Last edited column headers.
    What is wrong
    After sorting, only the arrow icon changes. Screen readers do not say "sorted ascending" or "descending".
    How to find it
    Accessibility pane: no sort property on the header.
    WCAG 2.2
    1.3.1 Info and Relationships, A
    The right way
    aria-sort="ascending" or "descending" on the sorted header, and the status region says how the list is now sorted.

  10. Every More actions button has the same name

    Where
    The three-dots button on each card and row.
    What is wrong
    All of them are called "More actions". In a list of buttons you cannot tell which agent each one belongs to.
    How to find it
    Screen reader: buttons list · Accessibility pane.
    WCAG 2.2
    Best practice: unique, descriptive names.
    The right way
    aria-label="More actions for Customer support bot", with the agent's name.

  11. More actions does not say whether its menu is open

    Where
    The three-dots button on each card and row.
    What is wrong
    The button has no aria-expanded, so a screen reader user does not hear that a menu opened.
    How to find it
    Accessibility pane: no expanded state.
    WCAG 2.2
    4.1.2 Name, Role, Value, A
    The right way
    aria-expanded="false" or "true", updated when the menu opens and closes, and aria-controls pointing at the menu.

  12. The More actions menu does not work like a menu

    Where
    The menu with Rename and Delete.
    What is wrong
    It says role="menu", but the focus stays on the button when it opens. The arrow keys do nothing, Rename and Delete are ordinary Tab stops, and Tabbing away leaves the menu open.
    How to find it
    Keyboard: open the menu, then try the arrow keys and Tab.
    WCAG 2.2
    Best practice: APG Menu Button pattern. Partly 2.4.3 Focus Order, A.
    The right way
    Opening the menu moves the focus to the first item. The arrow keys, Home, End and a letter move inside it, and Tab or Escape closes it.

  13. Escape closes the menu but loses the focus

    Where
    The More actions menu, after you Tab into it and press Escape.
    What is wrong
    The menu disappears together with the focused item, so the focus drops to the top of the page.
    How to find it
    Keyboard: Tab into the menu, press Escape, then Tab.
    WCAG 2.2
    2.4.3 Focus Order, A
    The right way
    Escape closes the menu and puts the focus back on the More actions button.

  14. Rename and Delete are not real dialogs

    Where
    The Rename agent and Delete agent dialogs.
    What is wrong
    The focus does not move into the dialog, and the page behind is not blocked: Tab and the screen reader both reach the content behind the dark overlay.
    How to find it
    Keyboard: open Rename, then press Tab a few times.
    WCAG 2.2
    2.4.3 Focus Order, A · 1.3.1 Info and Relationships, A
    The right way
    A native <dialog> opened with showModal(). The page behind becomes inert and the focus goes to the name field (Rename) or to Cancel (Delete, the safe choice).

  15. Closing a dialog loses the focus

    Where
    Rename and Delete, after Cancel, the close button or Escape.
    What is wrong
    The focus is not returned to the button that opened the dialog. The user has to find their place in the list again.
    How to find it
    Keyboard: open a dialog, cancel, then Tab.
    WCAG 2.2
    2.4.3 Focus Order, A
    The right way
    When the dialog closes, the focus goes back to the More actions button that opened it.

  16. Focus is lost after Save or Delete

    Where
    After renaming or deleting an agent.
    What is wrong
    The list is rebuilt and the focus drops to the top of the page, with no hint of what changed.
    How to find it
    Keyboard: rename an agent, then Tab.
    WCAG 2.2
    2.4.3 Focus Order, A
    The right way
    After Rename the focus goes to the renamed agent. After Delete it goes to the next agent, or to the heading if the list is empty.

  17. The current name is not selected in Rename

    Where
    The Agent name field in the Rename dialog.
    What is wrong
    The old name is not selected, so a keyboard user has to clear it by hand before typing.
    How to find it
    Keyboard.
    WCAG 2.2
    Best practice / usability.
    The right way
    The text is selected when the dialog opens, so typing replaces it.

Session 3: Settings page

Page structure: landmarks, headings, link names and language. The page only displays information, so every bug is in how it is built.

The page: seeded version · accessible version

  1. A second main area inside the first

    Where
    The whole middle column, from the Settings title down.
    What is wrong
    The content column has role="main", but it already sits inside the page's real <main>. A screen reader user finds two main areas, one inside the other, and cannot tell which is the page.
    How to find it
    axe DevTools with Best practices on (landmark-no-duplicate-main, landmark-main-is-top-level) · Landmarks bookmarklet · ANDI.
    WCAG 2.2
    Best practice: one main per page, not inside another landmark.
    The right way
    Only the one <main>. The column is a plain div.

  2. The Settings title is not a heading

    Where
    The large Settings title at the top.
    What is wrong
    It looks like the page heading, but it is a styled div. The page has no level 1 heading, and a screen reader user pressing H never hears what the page is.
    How to find it
    Headings bookmarklet · ANDI · axe DevTools with Best practices on (page-has-heading-one).
    WCAG 2.2
    1.3.1 Info and Relationships, A
    The right way
    <h1>Settings</h1>.

  3. Preferences looks like a heading but is not one

    Where
    The Preferences section title, between Profile and Notifications.
    What is wrong
    It looks exactly like the other section headings but is a paragraph. It is missing from every heading list, so the time zone, date format and email language seem to belong to Profile.
    How to find it
    Compare the headings list with what you see. No tool reports it.
    WCAG 2.2
    1.3.1 Info and Relationships, A
    The right way
    <h2>Preferences</h2>, the same level as the other sections.

  4. German text is not marked as German

    Where
    Preferences: the value "Deutsch" and the email preview below it.
    What is wrong
    The page is in English and these parts have no language of their own. A screen reader reads the German preview with English pronunciation, which nobody can understand.
    How to find it
    Read the page, then check the element in the Elements panel. The Lang bookmarklet shows only what is declared. No tool reports a missing lang.
    WCAG 2.2
    3.1.2 Language of Parts, AA
    The right way
    lang="de" on "Deutsch" and on the preview, so the screen reader switches to a German voice for those parts. The page itself, <html lang="en">, is correct.

  5. The word "off" is a heading

    Where
    Notifications: the grey OFF badge in "The weekly usage digest is switched off."
    What is wrong
    The badge is an h6, used to make it bold. A screen reader lists a level 6 heading called "off" in the middle of a sentence.
    How to find it
    Headings bookmarklet · axe DevTools with Best practices on (heading-order).
    WCAG 2.2
    1.3.1 Info and Relationships, A
    The right way
    A span with the badge style: the same look, no heading.

  6. Active sessions skips a heading level

    Where
    Security: the Active sessions heading above the devices table.
    What is wrong
    It is an h4 straight under the h2 Security, while the next heading, Recommendations, is an h3. The levels suggest a structure that is not there.
    How to find it
    Headings bookmarklet · axe DevTools with Best practices on (heading-order).
    WCAG 2.2
    Best practice: no skipped heading levels.
    The right way
    <h3>Active sessions</h3>, the same level as Recommendations.

  7. The recommendation headings skip a level

    Where
    Security, under Recommendations: Two-factor authentication, Session timeout, API keys.
    What is wrong
    They are h5 straight under the h3 Recommendations, with no level 4 between.
    How to find it
    Headings bookmarklet · axe DevTools with Best practices on (heading-order).
    WCAG 2.2
    Best practice: no skipped heading levels.
    The right way
    h4 for all three. The indent comes from CSS, not from the heading level.

  8. Three links all say only "Learn more"

    Where
    Security: the Learn more link under each recommendation.
    What is wrong
    In a links list, or tabbing from link to link, a screen reader user hears "Learn more" three times and cannot tell where each one goes.
    How to find it
    Screen reader: links list · ANDI Links module.
    WCAG 2.2
    Best practice (2.4.9 Link Purpose (Link Only), AAA). 2.4.4 at AA is met, because the heading just above gives the context.
    The right way
    Hidden extra text inside the link, for example "Learn more about two-factor authentication".

  9. The On this page navigation has no name

    Where
    The On this page links in the right-hand column.
    What is wrong
    The page has three navigations. Next to "Global" and "Main" this one is listed as just "navigation", with no hint of what it holds.
    How to find it
    Landmarks bookmarklet · ANDI · screen reader: landmarks list. axe does not report it.
    WCAG 2.2
    Best practice: name every landmark whose role appears more than once.
    The right way
    <nav aria-label="On this page">.

  10. The footer is in no landmark

    Where
    The footer at the bottom: the copyright line and the Privacy, Terms of use, Accessibility statement and Help links.
    What is wrong
    The footer is a plain div, outside every landmark. A screen reader user jumping between landmarks never reaches these links.
    How to find it
    axe DevTools with Best practices on (region) · Landmarks bookmarklet.
    WCAG 2.2
    Best practice: all content inside landmarks.
    The right way
    A <footer> next to <main>, with the links in <nav aria-label="Footer">.

Session 4: Monitoring page

A design handed over for review, so many findings are design decisions. Each one says what a reviewer would do: fix it in the design, clarify it with the designer or product manager, or implement it in code.

The page: seeded version · accessible version

The page as it loads

  1. The notices rotate and cannot be paused

    Where
    The Notice bar under the heading.
    What is wrong
    The notice changes every few seconds for ever, with no Pause, Previous or Next. Slow readers, screen reader users and magnifier users lose the text halfway. At high zoom the earlier notices cannot be reached at all. Review decision: fix.
    How to find it
    By eye: wait a few seconds.
    WCAG 2.2
    2.2.2 Pause, Stop, Hide, A
    The right way
    Previous, Pause and Next buttons and "2 of 4". The rotation also stops while the pointer or the focus is in the bar.

  2. The notice is cut off on a narrow screen

    Where
    The Notice bar at 320 px wide or 400% zoom.
    What is wrong
    The notice is forced onto one line and ends in "…", so most of it cannot be read. Review decision: fix, and clarify the narrow layout with the designer.
    How to find it
    Zoom to 400%, or make the window 320 CSS pixels wide.
    WCAG 2.2
    1.4.10 Reflow, AA
    The right way
    At narrow widths the notice wraps onto as many lines as it needs and the controls move to their own row.

  3. The metric labels have low contrast

    Where
    The four metric cards: the small label and the grey line under each number.
    What is wrong
    Light grey on white, about 2.5:1, too faint for many people to read. Review decision: fix.
    How to find it
    axe DevTools (color-contrast) · contrast checker.
    WCAG 2.2
    1.4.3 Contrast (Minimum), AA
    The right way
    A darker grey with at least 4.5:1.

  4. The response-time chart has no text alternative

    Where
    The P95 response time chart.
    What is wrong
    The chart is named only "P95 response time chart". A screen reader user learns that a chart exists, but not its values or trend. Review decision: clarify how the data is offered, then implement.
    How to find it
    Accessibility pane: read the chart's name · screen reader.
    WCAG 2.2
    1.1.1 Non-text Content, A
    The right way
    A short text summary above the chart, and a Show data as table button that reveals the values in a real table.

  5. The filters apply and close on every checkbox

    Where
    Services: the Filters button and its panel.
    What is wrong
    Ticking one checkbox filters the table at once, closes the panel and moves the focus. To pick two options you open the panel again and find your place again. Review decision: fix.
    How to find it
    Keyboard: open Filters, press Space on a checkbox.
    WCAG 2.2
    3.2.2 On Input, A
    The right way
    Checkboxes only change the selection. Apply filters and closes the panel, and Clear unticks everything.

  6. The service count is not announced

    Where
    Services: "Showing 6 of 6 services".
    What is wrong
    When the filters change, the count updates on screen, but a screen reader says nothing. Review decision: implement.
    How to find it
    Screen reader.
    WCAG 2.2
    4.1.3 Status Messages, AA
    The right way
    The count has role="status", so the new number is read without moving the focus.

  7. The services table is clipped when zoomed

    Where
    The Services table at 320 px wide or 400% zoom.
    What is wrong
    The right-hand columns, with the Edit buttons, are cut off and cannot be scrolled to. Nothing can be edited at that size. Review decision: fix.
    How to find it
    Zoom to 400%, or make the window 320 CSS pixels wide.
    WCAG 2.2
    1.4.10 Reflow, AA
    The right way
    The table scrolls sideways inside its card. Tables may scroll; losing functions is what fails.

  8. The threshold dialog has no error handling

    Where
    Edit on a service, then the Edit alert threshold dialog.
    What is wrong
    Only the browser's short bubble messages appear. A critical threshold lower than the warning one is saved silently, and the hint under Critical is not connected to its field. Review decision: clarify the rules, implement the messages.
    How to find it
    Keyboard: enter a critical value below the warning value, then Save.
    WCAG 2.2
    3.3.1 Error Identification, A · 3.3.3 Error Suggestion, AA · 3.3.2 Labels or Instructions, A
    The right way
    Each wrong field gets a message under it that says how to fix it, linked with aria-describedby and marked with aria-invalid. The focus moves to the first wrong field.

  9. The threshold dialog hides the current value

    Where
    The Edit alert threshold dialog.
    What is wrong
    The dialog covers the table, so you have to remember the current response time while choosing a threshold. Review decision: clarify.
    How to find it
    By eye.
    WCAG 2.2
    Best practice / usability.
    The right way
    The dialog shows the current P95 and its trend next to the fields.

  10. The Threshold saved message is not announced

    Where
    The green message at the bottom right after Save.
    What is wrong
    It appears for a few seconds, but a screen reader does not read it, so a blind user does not know that the save worked. Review decision: implement.
    How to find it
    Screen reader.
    WCAG 2.2
    4.1.3 Status Messages, AA
    The right way
    The message has role="status".

After Load more panels

The button at the bottom of the page adds a second batch of panels.

  1. Load more panels loses its name while loading

    Where
    The Load more panels button, just after you press it.
    What is wrong
    The button text is replaced by an empty spinner, so for a moment the button has no name and nothing says that something is loading.
    How to find it
    axe DevTools right after the click (button-name) · screen reader.
    WCAG 2.2
    4.1.2 Name, Role, Value, A · 4.1.3 Status Messages, AA
    The right way
    The button says "Loading…" and the status region announces "Loading more panels".

  2. Focus is lost when the panels appear

    Where
    Right after the second batch has loaded.
    What is wrong
    The focused button is removed, so the focus falls back to the top of the page.
    How to find it
    Keyboard: press Enter on Load more panels, then Tab.
    WCAG 2.2
    2.4.3 Focus Order, A
    The right way
    The focus moves to the Incidents heading, and a status message says what was added.

  3. The session expires with no way to extend it

    Where
    The pink banner "Still there? Your session expires in 1:00".
    What is wrong
    A one-minute countdown runs out and there is no button to extend it. People who read or type slowly lose their session.
    How to find it
    By eye: wait a minute.
    WCAG 2.2
    2.2.1 Timing Adjustable, A
    The right way
    A Stay signed in button restarts the timer and announces "Session extended".

  4. The Live dot blinks for ever

    Where
    Incidents: the red dot before Live.
    What is wrong
    The dot blinks once a second without end and cannot be stopped, which distracts people with attention difficulties.
    How to find it
    By eye.
    WCAG 2.2
    2.2.2 Pause, Stop, Hide, A
    The right way
    The dot is steady.

  5. The incidents refresh every 20 seconds and cannot be stopped

    Where
    Incidents: "Refreshes every 20 s".
    What is wrong
    Every 20 seconds the list resets: Show resolved is unticked, the table jumps back to page 1 and the keyboard focus is lost.
    How to find it
    Tick Show resolved or go to page 2, then wait 20 seconds.
    WCAG 2.2
    2.2.2 Pause, Stop, Hide, A · 2.4.3 Focus Order, A
    The right way
    An Auto-refresh checkbox turns it off, and a refresh keeps the user's page, filter and focus.

  6. The instructions rely on colour and position

    Where
    Incidents: the sentence under the heading.
    What is wrong
    "Incidents with a red dot … use the button on the right of the row" only works for someone who sees the colour and the layout.
    How to find it
    By eye · screen reader.
    WCAG 2.2
    1.3.3 Sensory Characteristics, A · 1.4.1 Use of Color, A
    The right way
    "Incidents with severity Critical need attention. Use Acknowledge to take one."

  7. Severity is only a coloured dot

    Where
    Incidents table: the Severity column.
    What is wrong
    There is no text, so a screen reader reads an empty cell and colour-blind users cannot tell Critical, Major and Minor apart.
    How to find it
    By eye · screen reader.
    WCAG 2.2
    1.4.1 Use of Color, A · 1.1.1 Non-text Content, A
    The right way
    The word, Critical, Major or Minor, next to the dot.

  8. Acknowledge is invisible until you hover

    Where
    Incidents table: the Acknowledge button in open rows.
    What is wrong
    The button is transparent until the mouse is over the row. Keyboard users Tab onto a control they cannot see, and touch users never see it.
    How to find it
    Keyboard: Tab through a row.
    WCAG 2.2
    2.4.7 Focus Visible, AA
    The right way
    Acknowledge is always visible.

  9. Focus is lost after Acknowledge

    Where
    Incidents table, after pressing Acknowledge.
    What is wrong
