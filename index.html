Accessibility training playground

A small fake application for practising accessibility checks. It exists in two versions that look the same.

  • Accessible version
    The reference: native HTML first, ARIA only where it adds something.
  • Seeded version
    The same screens with deliberate accessibility bugs. Find them with the keyboard, the browser's accessibility tools, bookmarklets, axe DevTools or a screen reader. Fix one by editing the DOM in the developer tools, then check again. Reloading the page restores the bugs.

The mission: create an Agent without a mouse

  1. Load the page and press Tab once. What received focus first?
  2. Reach the "New project" button on the Projects page and press Enter. Where did the focus land?
  3. Within the dialog, Tab through it, then press Esc. Where does focus return?
  4. Open the dialog again, enter a project name and start an empty project. Where did the focus go after the page changed? What does the browser tab say?
  5. Reach the "Add Agent" button and trigger it. Can you see the focus indicator?
  6. Fill in the required fields and Tab through the rest of the form to reach the Save button. Could you see the focus indicator at every Tab stop?
  7. Save the new Agent and navigate backwards with Shift+Tab to reach the Back button.
  8. Trigger the Back button with Enter. Where did the focus land?

In the seeded version you may get stuck without a mouse. That is a finding, not a fault of the playground: note where it happened, use the mouse to continue, and carry on.

Then try the Projects toolbar

  1. Back on the Projects page, start a screen reader and type part of a project name into the search box. What is announced when the list changes? Now type something that matches nothing.
  2. Move to the Card and List controls. What does the screen reader call them, and can you tell which view is active without looking?
  3. Switch to List. Use the screen reader's table commands to move along a row, then try to open a project without the mouse. Sort by Name: what is announced?

What to compare

Open both versions side by side and compare what the developer tools show for the same control: its name, its role and its state. Then compare what a screen reader says about it.

Nothing you enter is saved. The source is on GitHub.
